> **Python 期末專案 | 2025**

## 1. 專案動機

### 1.1 問題背景

台灣股市有超過 2,000 檔上市櫃股票和 ETF，對一般投資人而言，要從中找出值得投資的標的是一大挑戰。傳統方法需要逐一查詢財報、計算指標，耗時且容易遺漏。此外，免費的財經 API 往往有嚴格的頻率限制，導致即時抓取資料不穩定。

### 1.2 解決方案

開發一個**智慧選股系統**，採用「離線優先 (Offline-First)」架構。透過穩健的背景下載器先將真實財務數據完整抓取並儲存，讓使用者在瀏覽時能享受極速且穩定的體驗。系統整合了財務指標分析、策略篩選、綜合評分以及最新的 AI 自然語言選股功能。

### 1.3 專案目標



| 目標 | 說明 |
|------|------|
| **真實數據** | 堅持使用 FinMind 真實股市資料，拒絕隨機模擬數據 |
| **穩健下載** | 實作嚴格速率限制的下載器，克服 API 頻率限制 |
| **極速瀏覽** | 資料在地化儲存，查詢與篩選完全零延遲 |
| **AI 賦能** | 支援自然語言查詢（如：「找高股息且低負債的股票」） |

## 3. 資料來源與策略

### 3.1 核心策略：離線優先 (Offline-First)

為了徹底解決 API 頻率限制導致的資料缺失問題，本專案採用了創新的資料處理流程：

1.  **背景下載 (Write)**：
    *   使用 `scripts/robust_download.py`。
    *   嚴格遵守每 6 秒一次請求的限制（避開 402/429 錯誤）。
    *   支援斷點續傳，確保數據 100% 下載完成。
2.  **前端讀取 (Read)**：
    *   Web App 僅讀取 `robust_indicators_data.csv`。
    *   **優點**：速度極快、無 API 呼叫成本、資料絕對穩定。

### 3.2 資料內容 (FinMind)

| 資料集 | 內容 | 用途 |
|-------|------|------|
| `TaiwanStockFinancialStatements` | ROE, ROA, EPS, 負債率 | 基本面分析 |
| `TaiwanStockPER` | PE, PB, 股價 | 估值與即時股價 |
| `TaiwanStockDividend` | 現金股利, 配息年數 | 殖利率分析 |

### 3.3 精選股票池與選擇邏輯

本專案鎖定 **120 檔** 核心標的，其選擇原因與考量如下：

1.  **API 限制與穩定性平衡 (核心原因)**：
    *   FinMind 免費版 API 有嚴格的頻率限制 (每分鐘約 10 次)。
    *   若下載全台股 2000 檔，單次完整更新需耗時數十小時，對於期末專案展示或一般個人使用均不切實際。
    *   **120 檔** 的下載時間約 30-40 分鐘，是「資料完整度」與「使用者等待時間」的最佳平衡點。

2.  **80/20 法則的實踐**：
    *   這 120 檔股票（包含台灣 50、中型 100）涵蓋了台股 **85% 以上的總市值**與 **90% 的成交熱度**。
    *   包含台積電 (2330)、聯發科 (2454) 及熱門 ETF (0050, 0056)，已能滿足大多數投資人的分析需求。

**清單組成：**
*   台灣 50 成分股 (50 檔)：市場權值核心
*   中型 100 部分代表股 (50 檔)：中型成長股代表
*   熱門 ETF (10 檔)：存股族最愛
*   精選熱門股 (10 檔)：近期交易熱絡標的

## 4. 系統設計決策 (System Design)

本系統採用 **「減法設計」** 與 **「80/20 法則」**，將數百種金融指標收斂為 **11 個關鍵指標**，以平衡「分析深度」與「系統效能」。

### 4.1 四大核心維度 (Core Pillars)
系統建立在價值投資的四大支柱之上，構成最小可行性核心：
1.  **獲利能力 (ROE)**：權重 40%，衡量資本運用的絕對效率。
2.  **估值水準 (PE)**：權重 30%，利用 10-20 倍區間過濾合理價格。
3.  **現金回報 (Yield)**：衡量防禦性資產的實質回饋。
4.  **風險控管 (Debt)**：作為熔斷機制，直接排除高風險企業。

### 4.2 驗證與排除機制
*   **驗證層 (QA)**：利用「毛利率、營益率」驗證 ROE 品質；利用「PB」輔助判斷景氣循環股。
*   **工程權衡**：刻意捨棄「流動比」與「短期成長率」，因為它們需要額外 3 倍的 API 請求，且雜訊較多。我們選擇用「負債比」與「獲利品質」作為更穩健的代理指標。

## 5. 資料計算邏輯 (Calculation Logic)

為了確保數據在 API 變動下的穩定性，我們實作了混合式的計算策略：

### 5.1 雙重 ROE 算法 (Dual-Strategy)
*   **策略 A (優先)**：利用數學恆等式 $ROE = PB / PE$ 推算，數據來源最穩定。
*   **策略 B (備案)**：使用傳統會計公式 $\frac{\text{淨利}}{\text{權益}} \times 4$ (年化)，確保在缺乏 PE 值時仍有數據可用。

### 5.2 原始數據重組
API 僅提供原始會計科目 (Raw Data)，系統自行編寫演算法計算比率：
*   **獲利三率**：由 `Revenue`, `GrossProfit`, `OperatingIncome`, `NetIncome` 算出。
*   **殖利率**：結合 `Dividend` 資料庫的現金股利與 `PER` 資料庫的收盤價進行即時計算。

## 6. 核心功能亮點

### 6.1 🤖 AI 智慧選股 (New!)

*   **自然語言介面**：使用者不需懂複雜的篩選介面，直接輸入「我要找高股息且低本益比的股票」。
*   **語意解析**：系統自動將口語轉換為 `Yield > 5%` 和 `PE < 15` 等程式邏輯。
*   **策略匹配**：自動辨識使用者意圖屬於「價值股」、「成長股」還是「存股族」。

### 6.2 🏆 綜合評分系統

將複雜的財報數據簡化為 **0-10 分** 的直觀分數：

| 指標 | 權重 | 說明 |
|------|------|------|
| **ROE** | 40% | 獲利能力核心，越高越好 |
| **PE** | 30% | 估值核心，合理區間(10-20)得分最高 |
| **負債率** | 15% | 安全性，越低越好 |
| **PB** | 15% | 資產價值，越低越好 |

> **針對 ETF 的動態評分機制**：
> 考量 ETF 無 ROE 與負債比概念，系統採用**動態雙因子模型**：
> *   **情境 A（PB 有值）**：殖利率 **70%** + PB **30%**
> *   **情境 B（PB 無值）**：殖利率 **80%** + 配息年數 **20%**

### 6.3 📊 四大內建策略

1.  **🚀 成長股**：鎖定高 ROE、高淨利與良好財務結構。
2.  **💎 價值股**：尋找被低估的優質公司 (低 PE/PB)。
3.  **💰 高股息**：專為存股族設計，穩定配息且高殖利率。
4.  **⭐ 優質股**：財務穩健、獲利穩定的績優生。

## 7. Python 關鍵技術應用 (Python Implementation)

本專案充分運用的 Python 語言特性與生態系優勢：

### 7.1 資料科學核心 (Pandas & NumPy)
*   **向量化運算 (Vectorization)**：在計算 120 檔股票的綜合評分時，不使用慢速的 for 迴圈，而是利用 Pandas 的向量化操作，達成毫秒級的運算速度。
*   **資料清洗 (Data Cleaning)**：使用 `fillna()`, `dropna()` 處理財報缺漏值，確保計算穩定性。
*   **多表合併 (Merging)**：將財務報表、股利政策、即時股價等不同來源的 DataFrame 透過 `pd.merge()` 整合為單一總表。

### 7.2 現代化 Web 開發 (Streamlit)
*   **Pure Python UI**：完全不寫 HTML/CSS/JS，僅用 Python 邏輯即可構建互動式網頁。
*   **狀態管理 (Session State)**：建立跨頁面的資料傳遞機制（例如：在篩選頁選出的股票，可帶入分析頁查看）。
*   **效能快取 (Caching)**：使用 `@st.cache_data` 裝飾器，自動快取 API 回傳結果與運算後的 Dataframe，大幅提升使用者體驗。

### 7.3 穩健的網路程式設計 (Robust Networking)
*   **防禦性程式設計**：在 `robust_download.py` 中廣泛使用 `try-except` 區塊處理網路異常與 JSON 解析錯誤。
*   **速率限制器 (Rate Limiter)**：實作 `time.sleep()` 機制與時間戳記檢查，精確控制 API 请求頻率，解決 402 Payment Required 問題。
*   **自動重試機制**：針對網路波動設計了自動重試邏輯，提升爬蟲穩定度。

### 7.4 軟體工程實踐
*   **模組化設計 (Modularization)**：將程式碼拆分為 `src/data_fetcher.py` (資料層)、`src/stock_analyzer.py` (邏輯層)、`pages/` (展示層)，符合 MVC 架構精神。
*   **型別提示 (Type Hinting)**：全面使用 `typing` (List, Dict, Optional)，增加程式碼可讀性與 IDE 支援度。
*   **路徑管理 (Pathlib)**：使用 `pathlib` 取代傳統 `os.path`，解決 Windows/Mac 路徑相容性問題。

## 8. 專案成果與展望

### 8.1 成果總結

*   **解決痛點**：成功克服了免費 API 的限制，建立了穩定可靠的股票資料庫。
*   **體驗升級**：結合 Glarity 設計風格與 AI 對話介面，大幅降低了投資分析的門檻。
*   **數據誠實**：全面移除模擬數據，建立「無資料即留白」的誠實機制，提升信賴度。

### 8.2 未來擴充規劃 (Scalability)

若要從 120 檔擴充至全台股 (2000+ 檔)，系統設計可從以下方向升級：

1.  **付費解除限制 (Paid Tier)**：
    *   最直接的解法。升級 FinMind 或其他財經 API 付費方案，提高 Request Limit，即可將下載腳本的 `sleep` 時間從 6 秒縮短至 0.1 秒，快速完成全市場更新。

2.  **分散式排程 (Distributed Scheduling)**：
    *   利用 GitHub Actions 或雲端 Server (如 AWS Lambda)。
    *   每天凌晨自動執行下載任務，採取「分批輪動更新」策略（例如每天更新不同的 500 檔），一週內即可輪完所有股票資料。

3.  **混合式架構 (Hybrid Mode)**：
    *   **Tier 1 (熱門股)**：維持 150-200 檔熱門股每日預先下載 (Pre-fetch)。
    *   **Tier 2 (冷門股)**：改採「On-Demand」模式，使用者查詢時才即時調用 API，並將結果快取 24 小時，兼顧涵蓋率與效能。
